# 《合金文字機甲》IRONGLYPH — 近戰／遠程戰鬥系統設計

> 本文件定義**玩家與敵人雙方**的近戰／遠程動詞如何與既有的「令 × 部件」單槽系統、
> 五行相剋、部件掉落循環整合。對應 **Task 2.7**，執行順序排在 Task 4.1a（序章教程關）**之前**。

## 1. 問題陳述

### 1.1 玩家側：只有一個攻擊動詞

按住 `fire`(J) → `WeaponManager.fire(facing_dir)` → 生成 `Bullet`。
不論裝備什麼，最終都是「往面向方向丟出一顆會飛的 Area2D」。

`weapons.json` 其實**已經預留了近戰的資料欄位，但程式碼完全沒讀**：

| id | 部首 | 名稱 | `projectile` | `range` | 實際行為 |
|---|---|---|---|---|---|
| `dao` | 刂 | 近戰刀 | `melee` | `melee` | **飛出去的刀** ← 資料說近戰，程式當投射物 |
| `mu` | 木 | 藤蔓刺 | `vine` | `short` | 與長距離武器完全相同的飛行 |
| `jin` | 金 | 暗器 | `blade` | `long` | 同上 |

`WeaponManager.fire()` 只讀 `damage`／`element`／`fire_rate`／`pattern`／`projectile_count`，
`Bullet` 只有固定 `speed=500` 與 `max_lifetime=3.0`。十把武器在**手感層面只有傷害與射速的差別**。

### 1.2 敵人側：分化存在，但近戰敵人不是真的在近戰

三種 AI 都已實作且行為真實：

| AI | 敵字 | 現況 |
|---|---|---|
| `patrol_ranged` | 河／湖／炎／鋼 | **真的射子彈**：射程 420px、間隔 1.6s、彈速 320（刻意比玩家的 500 慢，玩家才閃得掉） |
| `chase_melee` | 海／焰／焚／針／劍 | 朝玩家水平接近，**沒有攻擊動作**，靠 `Enemy._check_touch_damage()` 的接觸傷害 |
| `stationary_aoe` | 雨／灶／錘／樹 | 蓄力 0.5s（字形放大 tween 當預兆）→ 半徑 130 範圍傷害 |

**問題出在 `chase_melee`：它是一團會走路的接觸傷害，不是近戰攻擊者。**

- 沒有前搖 → 玩家**無從閱讀**，只能靠距離感硬躲
- 沒有後搖 → **沒有懲罰窗口**，打不出「擋下這一擊再反打」的節奏
- 傷害靠碰撞體重疊觸發 → 站位變成「推擠」而不是「對峙」

對照之下 `stationary_aoe` 反而是三者中唯一有預兆（0.5s 蓄力）的。玩家拿到有前搖、可讀、
可懲罰的近戰之後，這個不對稱會直接毀掉近戰的手感：**你的攻擊有節奏，敵人的沒有**。

## 2. 借鑑：三種業界成熟解法

### 2.1 Metal Slug — 接觸感應式近戰（contextual melee）

同一顆攻擊鍵，靠近敵人時自動變成刀擊。近戰傷害高於手槍，且**得分更高**——用計分獎勵
玩家承擔近身風險。
（[Metal Slug Wiki: Knife](https://metalslug.fandom.com/wiki/Knife)、
[Metal Slug Series/System](https://en.namu.wiki/w/%EB%A9%94%ED%83%88%EC%8A%AC%EB%9F%AC%EA%B7%B8%20%EC%8B%9C%EB%A6%AC%EC%A6%88/%EC%8B%9C%EC%8A%A4%ED%85%9C)）

**優點**：零學習成本、不佔按鍵。
**不適用之處**：玩家**失去選擇權**——貼臉時想射擊也會變成揮刀。本作的五行相剋讓「貼臉時
仍然想用屬性遠程攻擊」成為合理需求，接觸感應會把這個選擇吃掉。

### 2.2 Dead Cells — 雙武器欄（two weapon slots）

玩家同時攜帶兩把武器，各綁一鍵。設計目標是讓玩家的組合**持續變動**；近戰武器是後期為了
應付「某些區域不好打」才補進去的。
（[Gamasutra: Designing each of the 50 weapons in Dead Cells](https://www.gamedeveloper.com/design/designing-each-of-the-50-weapons-in-i-dead-cells-i-to-feel-distinctive)、
[Dead Cells Wiki: Weapons](https://deadcells.wiki.gg/wiki/Weapons)）

**不適用之處**：Task 2.6 已定案 **單槽** `CORE/FUSED/HELD`，且敘事上「令」一次只能借一個
部件（見 `docs/PROTAGONIST-令.md` 的「借」與「還」）。塞第二個槽會同時破壞玩法與敘事。

### 2.3 Hollow Knight — 本體能力 + 消耗型遠程 + 下劈

骨釘（近戰）是角色**自帶的、永遠可用**的基礎動作；法術（遠程）需要資源。
空中向下攻擊命中後會**彈起**（pogo），把攻擊動作變成移動能力。

**本作直接借用**：①「保底動作 vs 借來的力量」的分工；②下劈彈跳（見 3.5）。

## 3. 玩家側定案：字核近戰（K）＋ 部件遠程（J）

> **一句話**：近戰是「令」**自己的**能力，永遠可用；遠程是**借來的**部件能力。
> 部件不是在兩者之間二選一，而是決定**強化哪一邊**。

### 3.1 兩個動詞

| | **J（`fire`）遠程** | **K（`melee`，新增）近戰** |
|---|---|---|
| 來源 | 部件／融合配方 | 「令」的字核本身 |
| 屬性 | 依部件五行 | 預設 neutral；FUSED 染融合字屬性；持「刂」為金 |
| 距離 | 依 `range` 欄位（180／420／720px） | 中心往前 94px（見 3.4） |
| 定位 | 主要輸出、五行相剋主戰場 | 保底手段、消彈、打斷、位移 |
| 是否會斷 | 會（CORE 時只有弱弓） | **永遠不會** |

### 3.2 部件決定「強化哪一邊」

`weapons.json` 新增 `attack_type` 欄位（`"projectile"` / `"melee"`），由部件的
`fallback_weapon_id` 決定它強化哪個動詞：

| Loadout 狀態 | J 遠程 | K 近戰 |
|---|---|---|
| **CORE**（令） | 基礎弓「弓」7傷/0.3s（刻意偏弱） | 令筆擊 neutral |
| **FUSED**（令＋雨＝零） | 歸零爆發（八方向水屬彈幕） | 令筆擊**染水屬**，可吃 ×1.5 |
| **HELD・投射類**（氵火木土石金） | 該部件的 fallback 武器 | 令筆擊 neutral |
| **HELD・近戰類**（刂） | 退回基礎弓「弓」 | **刀刃筆擊：金屬性**，傷害↑範圍↑ |

**這條規則解決了 Dead Cells 式方案的最大風險**：玩家永遠同時擁有一個遠程與一個近戰選項，
不會因為撿到「刂」就沒有遠程手段、遇到 `stationary_aoe` 的「錘」束手無策。

**「刂」吃金屬性的後果（已定案，刻意保留）**：金剋木、被火剋。
- 森林關（Task 4.2）持「刂」打「樹／藤／林」×1.5，是明確的專武
- 火山關（Task 4.2）持「刂」打火屬敵人 ×0.6，**玩家應該把它彈出去（Q）換回中性令筆擊**
- 「劍」（metal, `chase_melee`）掉落 `blade` 部件 → **打贏一隻金屬近戰敵人才拿得到金屬近戰**，
  掉落循環與五行在此閉環

**敘事對位**：借來的部件只能強化你其中一種本事，你自己的筆擊才是那個永遠不會被收回的東西——
與「仁」靠掠奪來的「人字旁」拼湊完整性、最後被「主」收回，形成直接對照。

### 3.3 風險回報：為什麼玩家會願意靠近

1. **傷害效率高**：令筆擊 16 傷 / 0.45s ≈ 35 DPS，基礎弓 7 傷 / 0.3s ≈ 23 DPS
2. **能消彈**：判定框同時吃 `enemy_bullet` 層。這是終Boss「仁」賜俸三選一裡
   「**爭（格擋彈反）**」的機制雛形——Task 5.4 只要把「消滅」升級成「反射」，不必另造系統
3. **能打斷蓄力**（見 3.6）
4. **掉落物自動吸附**：近戰擊殺時部件飛向玩家，遠程擊殺留在原地要走過去撿。
   呼應 Metal Slug 用計分獎勵近身，但改用本作既有的部件循環，不必引入計分系統

### 3.4 距離與安全窗口

玩家與敵人的碰撞體都是 `52 × 64`，因此**接觸傷害發生在中心距離 ≤ 52px**。

近戰判定框 `72 × 56`，中心往面向方向偏移 `+58px` → 判定範圍 `22 ~ 94px`，
加上敵人半寬 26px，**有效命中距離為中心距 52 ~ 120px**。

```
玩家中心                     判定框                    最遠命中
   |----------52px----------|=========|----------------|
   0        （接觸傷害）      22      94              120px
            ← 危險區 →        ← 安全揮擊窗口 68px →
```

**這 68px 的安全窗口就是近戰的技術深度**：站在窗口外緣揮擊可以完全不吃接觸傷害，
貼太近則是拿血換輸出。序章教程（Task 4.1a）應該用一隻「針」來教這件事。

### 3.5 下劈（pogo）— 攻擊即位移

**空中按 `move_down` + K** → 判定框轉到腳下（`56 × 72`，中心偏移 `+52px` 向下）。

| 命中對象 | 結果 |
|---|---|
| 敵人 | 造成傷害 + 玩家彈起 `-340` 速度，**跳躍次數重置** |
| 敵方子彈 | 消滅子彈 + 玩家彈起（同上） |
| 地形／落空 | 無事發生，正常下落 |

**設計意義**：把攻擊動作變成移動能力，這是本作垂直關卡設計的核心資源。
連續下劈可以在一排敵人／彈幕上跳過深淵——`max_jumps = 2` 的二段跳只能上升約兩倍跳躍高度，
下劈是唯一的「無限上升」手段，但需要下方持續有可踩的目標。

⚠️ **`move_down` 需要新增 Input Action**（S 鍵）。S 目前只綁在 Task 4.0 新增的 `menu_down`
（對話選項游標），兩者不衝突——對話期間整棵樹暫停，玩家無法揮擊。

⚠️ **彈起速度 `-340` 刻意小於一般跳躍的 `-420`**：單次下劈不能比跳躍飛得更高，
否則玩家會發現「下劈上升」比跳躍更划算，導致所有平台段都變成下劈。

⚠️ **對關卡設計的約束（Task 4.1 前置決策）**：一旦下劈存在，任何「敵人站在深淵上方」的擺位
都等於送給玩家一條過關捷徑。水域關的平台間距必須假設玩家可能有下劈資源。

### 3.6 近戰打斷蓄力

**近戰命中 `stationary_aoe` 敵人的蓄力階段（`_telegraph_left > 0`）→ 蓄力取消，敵人硬直 0.35s。**

- **只有近戰能打斷，遠程不能**——這是「為什麼要靠近錘／灶」的唯一答案
- 打斷後進入 0.35s 硬直，玩家可以再補 1 下（0.45s 冷卻下勉強來得及），是明確的獎勵
- 打斷不重置 `pulse_interval` 冷卻，避免玩家站在原地無限打斷把敵人鎖死

⚠️ **打斷必須有顏色與文字回饋，不能只把縮放彈回去。** 實機驗證時「字形有沒有縮回原狀」
靠肉眼比對根本分辨不出來。因此：蓄力染成警示橙並放大到 1.4（原本 1.25 太微妙）、
硬直期間染成灰藍讓玩家看得出「現在可以免費打它」、打斷瞬間飄出「打斷！」字樣。
⚠️ 染色用 `self_modulate` 而**不是** `modulate`——`HanziSprite.flash_hit()` 受擊閃紅用的是
`modulate`，共用同一個屬性的話，蓄力中被打一下就會互相把對方的 tween 蓋掉。
CanvasItem 這兩個屬性是相乘的，各自獨立 tween 不會打架。

⚠️ **打斷必須 kill 掉蓄力的 scale tween 並把 `hanzi_sprite.scale` 復原成 `Vector2.ONE`。**
`enemy_ai_stationary.gd` 的 `_start_telegraph()` 用 tween 把字形放大到 1.25 當預兆，
被打斷時若不處理，敵人會**永遠停在放大狀態**。這與 `HanziSprite.flash_hit()` 的
「連續受擊要先 kill 前一個 tween」是同一類問題。

## 4. 敵人側定案：讓近戰敵人真的會揮擊

### 4.1 `chase_melee` 改造：接觸傷害 → 有預兆的揮擊

沿用既有的 `ai: "chase_melee"` 資料值，**不需要遷移 `enemies.json` 的既有欄位**，
只在 AI 節點內部加上攻擊狀態機：

```
接近（到 attack_range 停下）→ 前搖 telegraph → 判定 active → 後搖 recovery → 循環
```

| 階段 | 行為 | 玩家可以做什麼 |
|---|---|---|
| 接近 | 水平朝玩家移動至 `attack_range` | 拉開距離 / 搶先揮擊 |
| **前搖** | 字形往玩家方向傾斜 + 閃色，**不移動** | **讀到預兆，這是撤退或搶攻的窗口** |
| 判定 | 開啟判定框 0.12s | 已經來不及躲，只能事前處理 |
| **後搖** | 定住不動 | **懲罰窗口：免費打一下** |

**`chase_melee` 敵人不再有接觸傷害**（`_check_touch_damage` 對這一型回傳 0）。
理由：既然有了可讀的揮擊，接觸傷害只會變成「讀對了預兆卻還是被蹭到血」的噪音。
`patrol_ranged` 與 `stationary_aoe` **保留**接觸傷害，作為玩家貼臉貼太久的反制。

### 4.2 三隻近戰敵人的差異化（純資料，不加新敵字）

`enemies.json` 每筆增加一個 `melee` 區塊，讓五隻 `chase_melee` 有不同的閱讀節奏：

| 敵字 | hp | 傷害 | 前搖 | 後搖 | 性格 |
|---|---|---|---|---|---|
| 針 | 22 | 9 | 0.18s | 0.20s | **快刺**：預兆極短，逼玩家保持距離而非硬換血 |
| 劍 | 40 | 18 | 0.45s | 0.55s | **重斬**：預兆長、後搖也長，是教「讀預兆→反打」的最佳教材 |
| 海 | 45 | 12 | 0.30s | 0.35s | 中庸 |
| 焰 | 35 | 14 | 0.28s | 0.30s | 中庸偏快 |
| 焚 | 38 | 13 | 0.32s | 0.35s | 中庸 |

**序章教程（Task 4.1a）用「劍」教近戰對峙**：0.45s 前搖足夠玩家反應，0.55s 後搖給出明確的
反打獎勵。等玩家學會了，水域關（Task 4.1）再放「針」，用短預兆考驗同一套技能。

### 4.3 雙方共用同一個 `MeleeAttack` 元件

玩家與敵人的近戰**用同一個節點腳本**，只有碰撞層與 profile 不同：

| | 玩家 | 敵人 |
|---|---|---|
| `target_mask`（打傷） | enemy(4) | player(2) |
| `block_mask`（消彈） | enemy_bullet(16) | 0 |
| 消彈 | ✅ | ❌（敵人不消玩家子彈，否則遠程完全失效） |
| 打斷 | ✅ | ❌ |

> **實作修正（2.7b）：判定不需要新增碰撞層。** 原本規劃 `player_melee`(6) / `enemy_melee`(7)
> 兩層給常駐 Area2D 用；改成即時形狀查詢後，判定框不再是場景裡的碰撞體，只是一次
> `intersect_shape` 的 mask，因此 `project.godot` 的 `[layer_names]` 完全不必動。
> 理由見 6.2。

**這是本設計最重要的結構決策**：戰鬥規則對雙方對稱，前搖／判定／後搖三段式是同一份程式碼。
日後調整「判定框要不要跟著角色移動」這類手感問題時只需要改一處，也讓 Boss（階段五）
可以直接複用同一套近戰，不必第三次實作。

## 6. 實作架構

### 6.1 檔案清單

**新增**
- `game/scripts/melee_attack.gd`（`class_name MeleeAttack`，extends `Node2D`）— 三段式揮擊
  生命週期、同一次揮擊去重、消彈、打斷、下劈彈起；玩家與敵人共用
- `game/data/melee.json` — 近戰 profile（傷害／前搖／判定／冷卻／reach／判定框）與下劈修正值。
  **不放進 `weapons.json`**：那是十把部首武器的 catalog，階段六 Task 6.2 的武器圖鑑直接讀它，

### 6.2 關鍵實作注意事項

⚠️ **判定改用即時形狀查詢，不用常駐 Area2D（2.7b 定案，與原規劃不同）。**
原本打算掛一個 Area2D、在判定期間開關 `CollisionShape2D.disabled`。實作時改成
`PhysicsDirectSpaceState2D.intersect_shape()`，三個理由：

1. 開關碰撞形狀必須走 `set_deferred()`（物理查詢 flush 期間不可同步改碰撞狀態，
   `Enemy.die()` 已經踩過），代表判定框「真正生效」比程式碼寫的晚一幀——
   0.12s 的判定窗實際只有 0.10s，而且時長會隨影格率漂移。
2. `get_overlapping_bodies()` 要等物理步進後才更新，判定的第一幀必然是空的。
3. 即時查詢**當幀就有結果**：測試不必猜要 await 幾幀，也不需要為近戰新增碰撞層。

⚠️ **查詢必須同時 `collide_with_areas`。** 子彈是 Area2D，只查 bodies 的話永遠消不到彈。
這與 Task 2.3 的「Area2D 的 `area_entered` 對 PhysicsBody2D 不觸發」是同一個坑的反面。

⚠️ **同一次揮擊只結算一次。** 判定窗在 0.12s 內橫跨多個物理影格，每幀都會掃到同一個目標，
需要 `_hit_this_swing` 以 instance id 去重——否則貼身揮一次會打出七、八下。

⚠️ **鏡像揮擊動畫時，掃描方向必須跟著一起翻。** 弧線用 `scale.x = -1` 鏡像形狀，
但旋轉的角度序列若維持不變，左揮就會從「由上往下劈」變成「由下往上撩」——
形狀對了、動作卻反了。螢幕 y 軸朝下，角度由負掃到正才是往下劈，
因此掃描的起訖角都要乘上 `signf(facing)`。**只翻形狀不翻方向，是鏡像動畫最容易漏掉的一半。**

⚠️ **視覺節點的位置要在 `add_child` 之後才設，而且設 `position` 不要設 `global_position`。**
節點還沒進場景樹時沒有父變換，Godot 的 `global_position` setter 會退化成 `set_position()`——
傳進去的世界座標被當成局部座標，加進場景樹後變成「父節點位置 ＋ 世界座標」，偏移量直接翻倍。
2.7b 的揮擊弧線就是這樣跑到腳下 120px 的位置，而且玩家離原點越遠偏得越多。
**寫這類測試時角色不要放在原點**——在 `(0,0)` 附近這個 bug 幾乎看不出來。

⚠️ **測試裡敵人的位置要在 `add_child` 之前設好。** 先 add_child 再移動的話，敵人會有一瞬間
出現在原點、與玩家完全重疊，物理去穿透會把玩家往旁邊推開整整一個身寬（52px），之後所有
距離斷言都是從錯誤的座標量出來的。2.7b 實作時就是這樣讓「正前方 80px 必中」變成落空。

⚠️ **傷害一律走 `Character.take_damage()`。** 基類已處理相剋倍率、hp 夾值、訊號與死亡去重；
`Enemy.take_damage()` 的註解說明了為什麼「先 super() 再閃紅」的順序不能改。

⚠️ **打斷要 kill 蓄力 tween 並復原 scale**（見 3.6）。

⚠️ **消彈只吃 `enemy_bullet` 層**，不可涵蓋 `player_bullet`，否則玩家會揮掉自己的子彈。

⚠️ **下劈彈起要在 `_physics_process` 內改 `velocity.y` 並重置 `_jumps_used`**，
不能只設 velocity——`Player._physics_process` 每幀都會 `apply_gravity`，順序錯了會被吃掉。
